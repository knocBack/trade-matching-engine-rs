# M2 — deterministic offline replay

**Requirement author:** M2 architecture scout (independent from scenario author and implementer)  
**Scenario author:** trade-rs-m2-scenarios crewmate (independent from implementer)  
**Implementation scope:** one local replay binary over the M1 library.

M2 accepts a fixed-registry canonical command JSON Lines tape and writes a canonical
event JSON Lines tape. The engine owns one `MultiSymbolBook` exclusively and processes
the physical command order sequentially. It calls M1 for all matching and cancellation;
it does not duplicate matching logic.

Input begins with `{"format":"trade-rs-command-tape","version":1,"symbols":[...]}`.
Symbols are nonempty, UTF-8-byte sorted, and unique. Commands are `limit`, `market`, or
`cancel`, with the exact field order defined in the M2 architecture report. JSON Lines is
strict: UTF-8 only; one final LF per record; no CRLF/BOM/blank lines/whitespace; no unknown
or duplicate fields; and canonical numbers and strings only. A malformed tape publishes no
new output and exits nonzero.

Each structurally valid command receives a contiguous index. It yields exactly one terminal
record: `command_completed` for M1 success or `command_rejected` for a domain error.
Effects precede completion and preserve M1 order. `Fill` becomes `trade_executed`; an
encountered same-owner maker becomes the ordered intermediate
`resting_order_cancelled` record with reason `self_trade_prevention`. That removal uses the
maker's complete live remainder and matching continues with the unchanged taker remainder.

Validation order is unknown symbol, then zero quantity, then duplicate live ID for new
orders; cancel validates symbol then emits `order_not_found`. Rejections produce no effects
and leave the book unchanged. Output is written to a fresh temporary file in the destination
directory and renamed only after complete decode, execution, and encoding succeed.

This M2 boundary has no network, HTTP, async runtime, ingress queue, persistence, database,
containers, or M3 route. Benchmark values are descriptive only, not an HTTP capacity claim.
