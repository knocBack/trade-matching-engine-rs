**Date:** 2026-09-16
**Requirement author:** `trade-rs-m0-requirements` crewmate (Codex)

## Executive conclusion

M0 should create only the smallest executable Rust foundation: a virtual Cargo workspace
using resolver 2, exactly one empty or documentation-only Rust-2024 library package at
`crates/orderbook` named `trade-orderbook`, a root lockfile, and one light GitHub Actions
workflow. It must add no order-book or application behavior and no runtime dependencies.

M0 must create one light GitHub Actions workflow. It must run the repository's canonical
formatting, Clippy, and test checks on all pull requests and on pushes to `main`.
`.no-mistakes.yaml` remains the source-controlled canonical command contract, and
no-mistakes remains the required local validation and PR pipeline. Because stable
`no-mistakes v1.72.0` cannot generate a runnable Rust-only workflow, the M0 implementation
may author this one workflow directly under the constrained exception in section 5. Local
acceptance separately includes an explicit workspace build.

M0 also establishes the milestone artifact convention by committing its independently
authored requirement and scenarios at `docs/requirements/M0.md` and
`docs/scenarios/M0.md`. The only pre-existing planning prose M0 may correct is the two safe
items from the post-merge audit: ADR-0006's stale present-tense 20k target wording and
README's nonexistent `learning/` layout entry. The M3 benchmark findings do not belong in
M0.

This requirement was derived without inspecting an M0 implementation. At the baseline,
none exists. A different person must author the scenarios from this requirement before
production implementation begins.

## Normative M0 requirement

The words **must**, **must not**, and **may** below are normative.

### 1. Purpose and completion outcome

M0 must leave a clean checkout with a minimal Rust workspace that Cargo can build and
validate, plus light hosted CI capable of reporting those canonical checks. It is a
foundation milestone, not the first order-book milestone.

M0 is complete only when every acceptance criterion in this report passes on the same PR
head, the PR body contains the required actual evidence, and the reviewer has recorded
both required verdicts. A local-only green result is incomplete. A workflow without a
green hosted pull-request run is incomplete.

### 2. Required tracked artifacts

The M0 change must add or change only this bounded surface:

- `Cargo.toml` — virtual workspace manifest.
- `Cargo.lock` — generated lockfile at the repository root.
- `crates/orderbook/Cargo.toml` — manifest for the sole workspace package.
- `crates/orderbook/src/lib.rs` — empty or crate-documentation-only library root.
- `.no-mistakes.yaml` — the source-controlled canonical command contract for the formatting
  check, Clippy with warnings denied, and tests; it must not prescribe an automatic priority
  score.
- `.github/workflows/ci.yml` — the sole workflow, containing the one minimal Rust CI job
  permitted by section 5. It may be authored directly for M0 because the current no-mistakes
  generator cannot produce a runnable Rust-only workflow.
- `docs/requirements/M0.md` — the committed M0 written requirement, including its author.
- `docs/scenarios/M0.md` — the independently authored M0 prose scenarios, including their
  author and the independence declaration.
- `README.md` — only removal of the nonexistent `learning/` layout entry.
- `docs/adr/0006-monolith-first.md` — only the safe target-wording correction described
  below.

No other tracked file is required or permitted by this milestone. In particular, M0 must
not add a binary, another crate, another workflow, a toolchain file, product tests,
benchmark code, infrastructure, or generated artifacts other than the root Cargo lockfile
and the sole minimal Rust workflow.

### 3. Cargo workspace contract

The root `Cargo.toml` must be a **virtual** workspace manifest:

- it has a `[workspace]` and no root `[package]`;
- `resolver = "2"` is explicit;
- its member list resolves to exactly `crates/orderbook`; and
- it contains no unrelated profiles, dependency catalog, lint policy, release tuning, or
  application configuration.

Cargo metadata must resolve exactly one workspace package and exactly one target. That
package and target must satisfy all of the following:

- package name: `trade-orderbook`;
- package location: `crates/orderbook`;
- package publication disabled with `publish = false`;
- Rust edition: `2024`;
- target kind: library only;
- library root: `crates/orderbook/src/lib.rs`; and
- library content: empty or crate-level documentation only, with no domain types,
  functions, state, algorithms, public behavior, executable entry point, build script,
  example, or benchmark.

Cargo-required metadata not named above must remain minimal and must not imply a product,
release, compatibility, or deployment commitment.

`Cargo.lock` must be committed at the repository root, be current for the manifests, and
have no nested counterpart. The workspace package must have no normal/runtime dependency.
Because M0 needs no helper library, it should have no build or development dependency
either; the lockfile must therefore introduce no third-party package.

### 4. Local acceptance commands

From a clean checkout at the PR head, all of the following commands must exit zero:

```text
cargo build --workspace
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

The formatting check must leave the worktree unchanged. Clippy warnings are failures,
including warnings from every target that M0 contains. `cargo test` is required even when
Cargo reports zero tests; M0 must not add a tautological test merely to make a nonzero test
count.

The PR must also validate the workspace shape using Cargo metadata rather than inferring it
only from directory names. At minimum, the evidence must show the results of:

```text
cargo metadata --no-deps --format-version 1
git status --short
git diff --check
```

Equivalent machine-readable metadata inspection is acceptable only if its actual output
still demonstrates the exact package count, package name, edition, publication setting,
target kind, dependency count, and workspace root.

### 5. Minimal GitHub Actions contract and constrained generator exception

`.no-mistakes.yaml` must remain the source-controlled canonical command contract, and
no-mistakes must remain the local validation and PR pipeline. The canonical hosted checks
are exactly:

```text
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

`.github/workflows/ci.yml` must be the only file under `.github/workflows/`. It must run
those three checks for every pull request and for pushes to `main`. The explicit
`cargo build --workspace` gate remains a local acceptance requirement; hosted
`cargo test --workspace` compiles the sole package, so M0 must not add a redundant hosted
build check.

Stable `no-mistakes v1.72.0` unconditionally emits `actions/setup-go@v5` with
`go-version-file: go.mod`. M0 must not contain `go.mod`, and `setup-go` fails when that
supplied file is absent before any Rust check runs. Therefore the M0 implementation may
author `.github/workflows/ci.yml` directly instead of producing it with
`no-mistakes ci-workflow`. This permission is limited to the one M0 workflow and the
current generator incompatibility. It is a constrained compatibility exception, not a
policy change: it does not waive `.no-mistakes.yaml`, the local no-mistakes gate, the
no-mistakes PR pipeline, hosted proof, or any other delivery requirement.

The workflow must contain no Go setup, `go.mod`, toolchain pin, matrix, cache, coverage,
scanner, release, benchmark, self-hosted runner, container, external service, or deployment
configuration. Beyond the checkout and minimum GitHub Actions job plumbing, its only
executable validation commands must be the three commands above. It must not add a fourth
hosted build step or any product behavior.

The PR must record the installed `no-mistakes` version and a reproduction using the
Rust-only canonical command contract that shows the generator's emitted
`actions/setup-go@v5` / `go-version-file: go.mod` block. It must record that a missing
supplied version file fails `setup-go` before the Rust checks, and explain why direct
authorship is this constrained compatibility exception rather than a change to no-mistakes
policy. The reproduction must be performed without replacing the final conforming workflow.
The PR must include the final workflow diff and a successful hosted pull-request run for the
exact reviewed head.
