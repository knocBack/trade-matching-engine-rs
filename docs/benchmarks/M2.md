# M2 descriptive benchmark evidence

This is a baseline, not a release gate or an M3 HTTP-capacity claim.

**Run:** 2026-09-17, local unladen release build  
**Implementation commit:** `64fbb8388a1b66f880957b53ce0bebeacccb1f5d`  
**Toolchain:** rustc 1.87.0 (LLVM 20.1.1), `aarch64-apple-darwin`  
**Host:** Apple M1, 8 logical CPUs, macOS 15.7.3  
**Profile:** Cargo `bench` / optimized release; Criterion sample size 10, measurement time 10 ms.

| Surface | Fixture | Result |
| --- | --- | --- |
| Codec decode | Canonical header plus two commands, in memory | 3.67–3.97 µs per tape |
| Replay in memory | Same tape, decode + M1 execution + event encode | 4.94–5.39 µs per tape |
| Engine loop | One pre-rested maker, one M1 fill, event materialized | 336–384 ns per command |
| Full replay | Release binary; 4-command prevention-and-continuation fixture; atomic file publication | 0.63 s wall, 476 input bytes, 1,126 output bytes |

The full-process number is deliberately a small cold-run smoke baseline and includes process
startup and filesystem work; it is not matching latency. The Criterion cases keep parsing,
encoding, and engine costs separately. Re-run with a longer fixture and a controlled thermal
state before comparing performance changes.
