## Scenarios

### S1 — Clean baseline, artifacts, and independent authoring (criteria 1 and 2)

Given the merged `main` baseline named by the requirement, when the reviewed M0 PR head is assessed, its diff must contain only the bounded M0 work and no unrelated pre-existing or implementation work. `docs/requirements/M0.md` and this independently authored `docs/scenarios/M0.md` must both be present.

Recorded identities must establish that the requirement and scenario/test authors differ; the implementer is neither scenario/test author nor reviewer; and the reviewer is neither implementer nor scenario/test author. Evidence must show that the scenario artifact predates production implementation. A local green checkout, a late scenario document, or role labels without identity evidence never satisfies this scenario. The requirement author may review, but cannot substitute for the independent scenario/test author.

### S2 — One virtual workspace (criterion 3)

Given Cargo resolves the root manifest, the root must be virtual—`[workspace]`, no root `[package]`—with explicit `resolver = "2"` and exactly one member, `crates/orderbook`. It must have no unrelated profiles, dependency catalogue, lint policy, release tuning, or application configuration.

This result must be demonstrated through resolved Cargo metadata, not inferred from directory names. A root package, an implicit or different resolver, or any second member fails.

### S3 — Exact sole package and target (criterion 4)

Given resolved Cargo metadata, exactly one workspace package must exist: non-publishable Rust-2024 `trade-orderbook` at `crates/orderbook`. It must expose exactly one target, a library rooted at `crates/orderbook/src/lib.rs`.

No binary, example, benchmark, build script, other target, other package, alternate package location, publishable package, or different edition is permitted. Correct naming alone does not satisfy the count and target boundaries.

### S4 — Empty foundation without product behavior (criterion 5)

Given the M0 diff and library root are inspected, `src/lib.rs` must be empty or crate-documentation-only, and no order-book or application behavior may appear anywhere in the change.

Domain types, functions, state, algorithms, public behavior, executable entry points, and tautological product tests are forbidden even if presented as harmless scaffold.

### S5 — Root-only current lockfile and no dependencies (criterion 6)

Given the final manifests and Cargo resolution, a current committed `Cargo.lock` must exist at the repository root and nowhere else. The sole package must have no normal/runtime dependency, and the lockfile must contain no third-party package. Since M0 needs no helper library, build and development dependencies are excluded too.

A nested or stale lockfile, direct or indirect third-party package, or runtime/build/development dependency fails this scenario.

### S6 — Four local gates on a clean reviewed checkout (criterion 7)

Given a clean checkout at the reviewed head, each command below must exit zero:

```text
cargo build --workspace
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

Formatting must leave the worktree unchanged. Clippy must emit no warning across every M0 target. Tests remain required even if Cargo reports zero tests, but M0 must not add a tautological test merely to obtain a nonzero count. Passing fewer commands, testing a dirty checkout, or claiming success without actual results fails.

### S7 — Narrow, directly authored Rust-workflow compatibility exception (criterion 8)

Given `.no-mistakes.yaml` is the source-controlled canonical contract, it must retain exactly the canonical formatting, Clippy-with-warnings-denied, and test commands; no-mistakes remains the required local validation and PR pipeline. The one permitted direct-authorship exception is `.github/workflows/ci.yml`, the sole file under `.github/workflows/`.

The PR must record `no-mistakes v1.72.0` and a disposable reproduction using the Rust-only canonical contract: `no-mistakes ci-workflow --force` emits `actions/setup-go@v5` with `go-version-file: go.mod`; because M0 must have no `go.mod`, that Action fails for the absent supplied version file before any Rust check runs. It must explain that direct authorship of this single minimal workflow is constrained compatibility handling for that current generator failure, not a change in `.no-mistakes.yaml`, no-mistakes local validation, no-mistakes PR-pipeline policy, hosted-proof requirements, or any other delivery rule. The reproduction must not replace the final conforming workflow.

The workflow itself must run exactly the three canonical Rust checks. It must contain no Go setup, `go.mod`, Rust toolchain pin, matrix, cache, coverage, scanner, release, benchmark, self-hosted runner, container, external service, deployment configuration, or fourth hosted build command. Checkout and minimal Actions job plumbing do not constitute an additional validation command.

### S8 — Exact hosted triggers and check scope (criterion 9)

Given GitHub evaluates the sole permitted workflow, it must run formatting, all-target workspace Clippy with warnings denied, and workspace tests for every pull request and every push to `main`. Its hosted validation scope is exactly those three light checks.

It must not omit or narrow either trigger, weaken warning denial, add a hosted `cargo build --workspace` step, or introduce matrices, caching, coverage, security scanning, release packaging, benchmark gates, self-hosted execution, containers, databases, external services, or deployment work.

### S9 — Successful hosted PR proof for the exact reviewed head (criterion 10)

Given the reviewed PR head, a GitHub-hosted pull-request workflow run for that exact commit must succeed. The PR evidence must supply the forge's full HTTPS run URL, workflow name, pull-request event, head SHA, and successful formatting, Clippy, and test results.

A push-only run, a run for any other commit, local validation, a screenshot without durable run linkage, or an unsupported “CI is green” statement is insufficient.

### S10 — Exactly two safe documentation corrections (criterion 11)

Given the permitted planning-prose corrections, ADR-0006 must call 20k RPS a later PRD budget while leaving its evidence-before-infrastructure argument intact, and README must no longer claim a nonexistent `learning/` layout entry.

M0 must not create `learning/` to make the old README statement true. It must not edit `docs/BENCHMARK.md` or import M3 benchmark/topology findings, including benchmark wording, co-location, acceptance floors, rejection semantics, workload topology, or measurement semantics. Additional documentation cleanup is outside M0.

### S11 — Bounded paths and all prohibited-scope absence (criterion 12)

Given the complete changed-file list and diff review, changes must stay within the enumerated M0 surface: root Cargo manifest and lockfile; sole crate manifest and library root; `.no-mistakes.yaml`; sole CI workflow; two M0 artifacts; README; and ADR-0006. `git diff --check` must succeed, and an exclusions inspection must find no forbidden choice or artifact.

The diff must add no other crate, binary, workflow, toolchain file, product test, benchmark code, or generated artifact beyond the root lockfile and sole workflow. It must not choose or imply order-book semantics, self-trade behavior, overload API behavior, runtime protocol or async model, product data structure, persistence, container/deployment topology, simulator/agent, benchmark configuration/result, logging/metrics/config/error framework, workspace-wide lint architecture, release configuration, or automatic priority score. Whitespace validity does not excuse a boundary violation.

### S12 — Complete, actual PR evidence including compatibility provenance (criterion 13)

Given the PR is submitted for review, its body must contain actual evidence for the exact reviewed head, not summaries or unsupported pass claims. It must state `P1 — normal planned foundation work`, say M0 is scaffold and light CI only with no automatic score, identify requirement author, scenario/test author, implementer, and reviewer, link both committed artifacts, and establish the required independence and pre-implementation order.

It must include the complete changed-file list and boundary review; Cargo metadata (or faithful relevant excerpt with full attached output) proving package/target/edition/publication/dependency/workspace and root-lockfile facts; actual output and zero status for every local gate, including an explicit statement when successful output is empty; and confirmation that formatting left the tree clean. It must include the v1.72.0 reproduction and missing-`go.mod` failure evidence specified in S7, the Rust-only canonical configuration, final direct-workflow diff, and scoped-exception explanation.

It must also include the full HTTPS hosted-PR-run URL and its workflow/event/head/results, documentation-validation results for both safe corrections, absence of M3 benchmark edits, valid relative Markdown links, and `git diff --check`. Finally it must account for end-to-end coverage: clean-checkout Cargo and hosted workflow runs are applicable M0 E2E validation; product property tests and product E2E behavior are inapplicable because M0 deliberately contains no product behavior. Omission of empty command output, this applicability rationale, compatibility-failure evidence, or durable reviewed-head hosted evidence fails.

### S13 — Two-part reviewer verdict and captain merge boundary (criterion 14)

Given evidence for every prior scenario, the reviewer must record two explicit, reasoned parts: (1) exactly `conforms` or `does not conform`, tied to numbered criteria and evidence; and (2) exactly `no focused captain attention needed`, or the exact decision, ambiguity, or risk requiring captain attention, with reasoning.

M0 becomes ready for the captain’s merge decision only when every applicable criterion passes on the same PR head, the complete evidence package is present, and both verdict parts are recorded. P1, a green check, local success, or either verdict alone never grants merge authority.
