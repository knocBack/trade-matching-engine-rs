# M3 HTTP-ingestion behaviour scenarios

**Author role:** independent M3 scenario/test author
**Status:** pre-implementation scenario specification
**Authoring boundary:** authored before inspecting any M3 production implementation or implementation branch. This is prose only, not test code or an architecture choice.

## Authority and scope

This report derives from the M3 HTTP-ingestion architecture requirement, the roadmap, delivery contract, accepted ADRs 0001–0007, completed M1/M2 scenario reports, and their self-trade-prevention amendments. M3 is a co-located Rust HTTP adapter around the deterministic M2 engine. It adds only POST /orders, DELETE /orders/:id?symbol=:symbol, and GET /book?symbol=:symbol; it neither changes M1 matching nor M2 event meanings.

“Admitted” means inserted once into the finite shared engine queue. Its single consumer is the only engine/book owner. An order command is POST or DELETE; a snapshot is GET. A command response is complete only after the engine has produced its entire M2 event batch. “Immediate” overload means no await, retry, spin, or second queue while waiting for future capacity; it is a control-flow fact, not a latency threshold.

The scenario author, future implementer, and reviewer must be distinct people under the delivery contract. Event names/fields below are the settled M2 v1 vocabulary; the adapter preserves rather than redefines them.

## End-to-end HTTP scenarios

Each scenario uses a fresh configured server and real HTTP/1.1 requests. Evidence is complete status/body, relevant pre/post GET /book snapshots, server counters, and controlled engine/connection observations where named. JSON object-key order and insignificant whitespace are not compared; statuses, stable error codes, typed scalar values, arrays, and event order are.

### Strict route, method, and JSON boundary

| ID | Stimulus | Required observable result |
|---|---|---|
| H1 | Valid JSON limit POST with every required field, application/json, nonempty symbol, exact integer tick, and positive quantity. | 200 with an events envelope only after engine completion. Its batch ends in M2 command_completed and later queued snapshot shows the resting state. |
| H2 | Valid market POST: fully filled and no-liquidity cases. | Both are 200. Events preserve M2 effects followed by one completion, including filled or unfilled disposition. A market residual never appears in snapshot. |
| H3 | price_ticks at negative, zero, i64 minimum, i64 maximum where fixture permits; IDs/quantities at valid integer boundaries. | Valid integers reach M2 unchanged: no decimal/float conversion, rounding, wrapping, trimming, case folding, or Unicode normalization. |
| H4 | Zero-quantity limit and market POST to known symbol. | Structurally valid body reaches M2: 422 invalid_quantity, one command_rejected event, no state mutation. |
| H5 | Omit each required POST field; add unknown field/duplicate key; send non-object JSON, wrong type, bad side/type, fractional/exponent/non-integral number, negative/out-of-range unsigned number, out-of-range signed tick, or trailing non-whitespace. | 400 malformed_request before engine admission. No permissive defaulting or duplicate-key last-wins; counters and snapshot unchanged. |
| H6 | Missing/unsupported content type; application/json with permitted charset parameter. | Unsupported type is 415 unsupported_media_type with no mutation. Any accepted parameter decodes precisely like bare JSON and is documented. |
| H7 | Body exceeds configured finite limit (at most 16 KiB), including streamed body. | 413 body_too_large, no insertion; decoder stops rather than accumulating unbounded data. |
| H8 | Empty/whitespace symbol or invalid UTF-8/JSON wire. | 400 malformed_request and no symbol transformation/state change. |
| H9 | Body with GET; unsupported method on known route; unknown route. | GET body is malformed_request with no engine action; known unsupported method is 405 method_not_allowed; unknown route is 404 route_not_found. None becomes a domain result. |

Route selection and finite HTTP admission precede body accumulation. Consequently a recognized malformed request may yield 503 ingress_overloaded when no HTTP permit is available; once permitted, H5–H8 apply and no malformed request reaches M2. This precedence is explicitly tested.

## Admission, ordering, disconnect, and shutdown E2E scenarios

| ID | Controlled setup/action | Required observable result |
|---|---|---|
| Q1 | Pause engine before dequeue, fill finite queue, then independently issue POST, DELETE, and GET requests. | Each receives 503 ingress_overloaded while engine stays paused. No wait/retry/spin/alternate queue, command index, or book mutation. |
| Q2 | Exhaust finite in-flight HTTP admission before parsing/queueing another recognized request. | Immediate same 503 ingress_overloaded; no unbounded waiting layer ahead of queue. |
| Q3 | Begin graceful drain, close queue, or engine unavailable before admission. | 503 service_unavailable, no mutation; distinct from capacity-full code. |
| Q4 | Arrange observed queue order command C1, snapshot S, command C2 with distinguishable states. | S equals complete detached state after C1/before C2; snapshot consumes no M2 command index, no partial/merged view. |
| Q5 | Concurrent cross-symbol offers; record successful insertion/dequeue order. | Batches/snapshots follow that sole queue order; command indices contiguous from one for commands only. Socket/handler order is not guaranteed. |
| Q6 | Admit command then abort request/connection before completion. | Engine executes once FIFO; post-drain snapshot proves it. Completion-delivery failure counted as applicable; no rollback/retry/duplicate/replacement response. |
| Q7 | Disconnect before admission, then admit comparable request. | Disconnected unadmitted request has zero effect; later request works. This distinguishes pre-admission cancellation from post-admission loss. |
| Q8 | Graceful shutdown with queued commands/snapshots and a post-admission disconnect. | New/unadmitted work rejects; every admitted message drains FIFO through completion before exit. Connected clients receive responses where usable; disconnected command still executes once. No cancellation/reorder/retry/silent abandonment. |
| Q9 | Unexpected engine exit or lost completion sender after admission while client remains. | Stop admission/begin shutdown; client gets 500 completion_unavailable if usable, outcome explicitly uncertain. Never replace engine with empty one. |
| Q10 | Admit a command, deliberately keep engine paused beyond any ordinary request-processing deadline, then resume while client remains connected. | Handler remains waiting for its engine completion rather than manufacturing a server-side timeout; after resume it returns exactly the completed result once. |

## Model and property scenarios

These complement, not replace, E2E HTTP cases. They generate controlled typed M2 sequences and HTTP requests, compare a narrow independent oracle to responses/snapshots/counters, and preserve seeds, shrinks, and raw failure artifacts.

| ID | Generated/model property | Required oracle/evidence |
|---|---|---|
| M1 | HTTP-to-M2 parity across symbols, order forms, FIFO/depth, boundaries, rejections, self encounters. | Compare HTTP event meanings/order, status/code, each-prefix snapshot with direct sequential M2 for same admitted typed sequence. Transport cannot reinterpret matching, validation precedence, ID scope, or self trade. |
| M2 | One admission, one execution under saturation/cancellation. | Every insertion has one command index/terminal batch; every pre-admission failure has zero index/effect. Admission counts reconcile to terminal outcomes plus executing-at-cut; no duplicate effect. |
| M3 | Single ownership and boundedness under concurrent producers. | Only engine consumer mutates/snapshots. Queue, in-flight, and body limits finite positive fixed startup values; no shared-book lock/alternate unbounded queue. Evidence: ownership review plus saturation. |
| M4 | Queue-order/snapshot linearizability. | Snapshot equals M2 state after prior dequeued messages/before later; command indices follow consumer order, snapshots consume none. |
| M5 | Event finality for zero/multiple effects, typed rejection, prevention continuation. | Success is effects then one completion; rejection exactly one rejection only; no event after terminal; adapter never omits/sorts/coalesces. |
| M6 | Self-trade accounting with partial maker history, forms/sides, multi-symbol interleavings. | Prevention has equal owners, positive full current maker remainder, valid side/price/symbol, no self trade. Submitted equals third-party fills plus terminal remainder; prevention excluded. Maker original equals earlier fills plus prevention cancellation. Preserve FIFO, positive remainder, uncrossed books, isolation. |
| M7 | Strict-wire non-mutation in valid traces. | Wire-validation failures preserve snapshots/admission count and deterministic status/code. Deliberate permit exhaustion proves allowed 503 precedence separately. |
| M8 | Disconnect/drain independence across timing/shutdown cuts. | Pre-admission abort zero effect; post-admission disconnect one effect; graceful drain completes admitted FIFO work and rejects future work. |

## Status/error compatibility matrix

| Condition | Status/body |
|---|---|
| Completed POST/DELETE/snapshot | 200; order command events or detached book shape. |
| unknown_symbol / order_not_found | 404 plus one M2 rejection and matching code. |
| duplicate_order_id | 409 plus rejection/code. |
| invalid_quantity | 422 plus rejection/code. |
| Queue or finite admission full | 503 ingress_overloaded pre-engine envelope/no mutation. |
| Draining, closed queue, unavailable before admission | 503 service_unavailable pre-engine envelope/no mutation. |
| Oversize, unsupported media, malformed wire | 413 body_too_large; 415 unsupported_media_type; 400 malformed_request. |
| Known unsupported method / unknown route | 405 method_not_allowed / 404 route_not_found. |
| Lost unexpected completion after admission | 500 completion_unavailable; client outcome unknown and admission stops. |

Every JSON response declares application/json. Human-readable logging never replaces stable codes.

## Provisional HTTP-wall benchmark scenarios and evidence

The M3 gate is three fresh release-profile co-located loopback runs at **500 offered order-command requests per second**, client-observed HTTP-wall **p90 at or below one second**. HTTP-wall is full-response-read completion minus dispatch. GET is excluded from offered 500.

| ID | Scenario | Required observable evidence |
|---|---|---|
| B1 | Fresh process: preload deterministic fixture outside timing; verify snapshot; warm 30 seconds at 500 offered RPS; measure 120 seconds at 2ms open-loop schedule; stop offers, drain, collect counters/final snapshot, graceful stop. | Per-run raw samples and aggregate p50/p90/p95/p99/max for all completed commands, 200s, 503s, endpoint/mix categories; status/code count, accepted/completed throughput, rejection/timeout fraction, scheduling lag, offered-load response time. Never best run only. |
| B2 | Four-symbol round-robin: 50% unique non-crossing limit-buy POST q1, 25% market-sell POST q1 consuming preloaded high-tick buys, 25% DELETE distinct protected low-tick buys. | Exact symbols/ticks/IDs/preload amount (warmup + measurement + 10%), limits, connection count, final states. Domain rejection is fixture defect; 503 is overload evidence. |
| B3 | Open-loop independent of responses, bounded sufficient client concurrency, HTTP/1.1 keep-alive. | Per offer record scheduled, dispatch, completion/timeout, endpoint, status, code, response bytes. Client timeout >1s (10s recommended); no unbounded generator queue. |
| B4 | Judge all completed offered order commands. | p90 <=1s demonstrated only when >=90% offers complete; >=10% missing completion fails demonstration. Fast 503 never claims 500 successful commands/s; completion/rejection figures accompany headline. |
| B5 | Separately Q1 then stepped probes above 500 until overload or documented generator ceiling. 100K–500K optional points marked exploratory. | At each step report offered, dispatched, completed, 200, domain error, 503, timeout, connection error, admitted-command, engine-completed rates, queue high-water. Explicit overload proof is separate from p90 run. |

Record commit/cleanliness, Rust/tool/load-generator versions, exact commands/configuration, release profile, OS, CPU logical/physical counts, RAM, power/thermal state if known, affinity/isolation, co-located load, server limits, debug-log setting, raw artifact locations. Reconcile offers as response/failure/timeout/outstanding-at-cut and admissions as engine terminal/executing-at-cut after documented drain. The evidence report replaces/revises the provisional definition with observed evidence, never retroactively changes this gate.

## Delivery/review evidence and boundaries

Expose/log counters for recognized endpoint/status requests; commands admitted/completed/domain-rejected by reason; overload; queue current/high-water; snapshots admitted/completed/rejected; completion-delivery failures; graceful/abnormal exit. Reading them cannot mutate engine order or add wall-clock fields to M2 events.

The implementation PR carries this report, actual H–S/Q results, actual model/property output, limits/defaults, raw benchmark artifacts, and the two reviewer verdicts: requirement conformance and focused captain attention. It stays a bounded in-process adapter: no infrastructure/containers, TLS/HTTP2/gateway, auth, persistence/recovery, M4 egress, M5 timing, shared-book locks, per-symbol workers, or changed M1/M2 semantics.
